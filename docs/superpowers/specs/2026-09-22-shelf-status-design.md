# 货架状态页面设计

## 目标与范围

在移动端进料页面增加“货架状态”入口和只读状态页面。页面进入时自动采集两台现场信号采集器的离散输入（DI），并允许用户手动刷新。页面将每一个有效 DI 点映射到一个货架层位，显示该层位是否有货。

本功能不修改库存业务数据，也不将现场 DI 状态持久化到数据库。状态仅代表本次接口调用读取到的现场值。

## 现场状态规则

- 采用 Modbus TCP 功能码 `0x02` 从起始地址 `0x0000` 读取 104 个离散输入。
- 每台设备均读取 104 点；超出已配置货架层位的输入点不参与返回和显示。
- `0` 表示有货，`1` 表示无货。
- 每列固定为 3 层，排列顺序为第 1 层、第 2 层、第 3 层连续。

| 设备 | 地址 | 有效点数 | 映射顺序 |
| --- | --- | ---: | --- |
| 第一排 | `192.168.115.201:502` | 54 | `800001` 至 `800018`，每列第 1 至第 3 层 |
| 第二排 | `192.168.115.200:502` | 63 | `800030` 至 `800019`、`700027` 至 `700022`、`600003` 至 `600001`，每列第 1 至第 3 层 |

例如，第二排的 DI1、DI2、DI3 分别为 `800030X1501013`、`800030X1502013`、`800030X1503013`；DI63 为 `600001X3503013`。

## 架构与数据流

浏览器不直接访问设备的 TCP/502 端口。前端仅调用 WMS 后端接口，后端通过现有 `ModbusHelper` 与现场设备通信：

```text
货架状态页面 → WMS HTTP 接口 → ModbusHelper → 两台信号采集器
货架状态页面 ← 已映射的层位状态 ← WMS HTTP 接口 ← DI 读取结果
```

后端新增货架状态应用服务、DTO 和控制器接口。服务并行读取两台设备各 104 个 DI，分别将前 54 点和前 63 点映射为货架层位。返回结果按“排”分组，每个层位至少包含货架层编码、货架编号、层号和状态值。

接口还会返回每台设备的采集结果和错误信息。读取失败时，该排不应被解释为“全部有货”；接口必须明确标记该排为采集失败，前端以异常状态展示。

## 接口契约

新增只读 HTTP `GET` 接口，响应包含：

- `refreshedAt`：服务端完成本次采集的时间。
- `rows`：两排货架状态。
- 每排字段：设备标识、设备地址、是否读取成功、错误信息（失败时）、层位集合。
- 每个层位字段：货架层编码、货架编号、层号、DI 序号、`status`（`0` 有货，`1` 无货）。

所有 104 个输入均由后端读取，但只有上述有效点出现在 `rows` 中。接口不得返回现场设备的控制能力，也不得写入设备或库存。

## 后端实现约束

现有 `ModbusHelper.ReadMachineStatusAsync` 在通信异常时返回全 `false` 数组，无法区分“读取成功且 DI 全为 0”和“采集失败”。本功能新增带成功标识的读取方法或内部结果类型，保留原有方法以避免影响既有调用方。

读取时应校验 Modbus 响应满足预期的功能码、数据字节数和完整数据长度；发生连接、超时或响应格式异常时，返回失败信息。单台设备失败不得阻止另一台设备的状态返回。

货架映射应由集中且可测试的配置/生成逻辑构造，不能散落在控制器或 Vue 模板中。货架编号、规格段（`15`、`25`、`35`）和三层编码需符合现场约定。

## 前端交互与展示

在现有移动端进料页面添加“货架状态”入口并新增路由页面。

页面首次挂载时请求接口一次，并显示加载状态。用户可点击“刷新状态”重新请求；请求进行中禁用按钮，防止并发刷新。

页面按两排展示：每列标注货架编号，并按第 1、2、3 层显示可识别状态。`0` 用绿色“有货”显示，`1` 用红色“无货”显示。页面显示最后刷新时间和状态图例。若某排读取失败，该排显示采集失败及错误说明，另一排正常显示，不用默认值伪装为正常状态。

## 验证

为后端映射和状态解析添加聚焦测试，至少覆盖：

- 第一排 DI1 与 DI54 的编码、层号及状态映射。
- 第二排 DI1、跨字节的 DI9、最后的 DI63 的映射。
- DI64 至 DI104 不出现在接口响应中。
- `0` 映射为有货、`1` 映射为无货。
- 单设备读取失败时返回失败状态，另一排仍可正常返回。

前端进行类型检查或项目既有构建检查，并人工检查页面进入自动加载、手动刷新、颜色图例和异常排显示。
